## Числа в таблицах: до / после

Оба результата оценены одним текущим оценщиком по номеру таблицы, строке, столбцу и токену числа. Сохранены знаки, включая ± и минус с пробелом. Объединённые ячейки разворачиваются в позиции сетки. Поэтому считаются числовые позиции, а не уникальные значения; текст вне таблиц в эту таблицу не входит. Малое число верных позиций в старом результате может быть следствием сдвига строк или неправильного номера таблицы, а не отсутствия распознанных цифр.

## Что изменено и проверено

- Исправлены подписи таблиц с частичной пометкой `А.[?1]`, разрядкой букв, сокращением «табл.» и склеенным колонтитулом. Оценщик перестал приписывать их к чужой таблице.
- Крайние столбцы восстанавливаются по реально найденным горизонтальным линиям, даже когда крайних вертикальных линий нет. Совпадающие внутренние границы позволяют соединить оторванные части сетки.
- В широких сортаментах общие полосы числовых строк определяются до OCR ячеек. Сохраняются категории профилей, строки ниже последней горизонтальной линии и геометрически подтверждённые объединённые ячейки. Уже собранные строки повторно не делятся эвристикой.
- Числа не исправляются по смыслу или формулам. Расхождения и альтернативы остаются помеченными, вырезки сохраняются.
- JSON страниц записывается атомарно. Ночная очередь восстанавливает отсутствующий Markdown из готового JSON, обновляет прогресс и сохраняет ручные правки и отметки проверки. Проверен настоящий CLI на границе сбоя «JSON уже есть, Markdown ещё нет».
- Отчёт больше не теряет поздние страницы после первых 400 сомнений. После сборки выполняются безопасная проверка соотношений и CLI `relcheck.py`; оба используют одинаковую нумерацию таблиц и строк.
- Добавлена локальная ONNX-модель формул и выбор модели в панели. `install-formulas.bat` — отдельная первоначальная установка около 179 МБ моделей. Работает на CPU без видеодрайверов и без последующего скачивания. Модель заметно ошибается в сложных индексах и цифрах; весь LaTeX явно несверенный. Вырезка остаётся и при ошибке модели. Результат не объявляется точным.
- Обычный OCR, SERVER для числовых ячеек и локальные формулы повторно запущены с заблокированными Python socket-соединениями. Проверен API формул через локальную очередь.
- Режим precise проверен на отдельной таблице: 400 dpi, 3306×4678 пикселей, девять ячеек и голосование моделей. Это не полный прогон пяти ГОСТов в precise.

Выполнен полный прогон пяти ГОСТов в auto и ocr. После последних изменений геометрии повторена стадия таблиц из сохранённых слов: неизменённые вырезки использовали прежнее распознавание, изменённые — распознавались повторно. Затем для всех десяти сочетаний пересобран Markdown и пересчитана метрика. Это не десять новых полных запусков детектора после каждой мелкой правки.

34 модульных теста прошли. Проверки логики/HTTP пройдены локально; отдельные Windows-сборки GitHub Actions проверяют установку, модульные тесты и локальный HTTP-сервер. Точные результаты последних запусков видны во вкладке Actions.

## Ресурсы

Панель открывается в браузере, распознавание выполняет локальный Python. Установка требует скачивания библиотек и моделей на диск. PDF, изображения и Markdown также хранятся на диске.

Локальный процесс: не более половины логических ядер, максимум четыре. На Windows установлены пониженный приоритет и маска доступных CPU. Межпроцессная блокировка предотвращает одновременный OCR из панели и batch. Её освобождение после принудительного завершения процесса проверено тестом.

Перед подготовкой, страницами и ячейками проверяется запас ОЗУ: 20% общего объёма, минимум 1,5 ГБ. Перед рендером — оценка памяти и предел 45 Мп. Это предупредительные проверки, не жёсткая квота памяти и не гарантия отсутствия задержек при любой внешней нагрузке. Браузерный GLM — отдельное приложение; ограничения локального Python на него не распространяются.

Повторный небольшой тест: лист 900×1200, 20 логических CPU, бюджет 4, 2,257 с, средняя загрузка всей машины 16,09%, пик рабочего набора 256,2 МиБ. Это не худший случай большого PDF или precise.

## Что осталось или не подтверждено

1. Точность ещё недостаточна для использования чисел без сверки, особенно у ГОСТ 8240-97. Есть пропуски и ошибки распознавания/структуры. Нужно сокращать их, сохраняя нулевой показатель непомеченных ошибок.
2. Полный пятидокументный прогон precise не проведён. В установленном RapidOCR нет Cyrillic SERVER: русский текст читает MOBILE, SERVER используется для числовых ячеек.
3. Продолжения некоторых таблиц остаются отдельными HTML-фрагментами с общим номером. Оценщик и relcheck объединяют позиции, но единый HTML-блок по rules.md обеспечен не во всех случаях. Нечитаемые номера не угадываются.
4. Отдельного полного прогона пяти документов в двух режимах после каждого индивидуального подпункта первоначального задания нет. Есть полные прогоны и зафиксированные повторные оценки изменённых стадий.
5. Полностью автоматическая пакетная сверка LaTeX с человеком не реализована. Локальная модель установлена и работает офлайн, но точность сложных формул не подтверждена; браузерный GLM требует своей первоначальной загрузки около 650 МБ.
6. Реальный Chrome с разрешением доступа к локальной сети не проверен: браузер недоступен через подключённое управление. Локальная панель проверена во встроенном браузере. Основной способ — localhost; работа панели на сайте пока не обещается.
7. Установка проверена в новом venv и на Windows GitHub Actions, но ручной запуск start.bat на отдельной чистой пользовательской машине и многочасовая работа при нагрузке другими приложениями не проверены.
8. Восстановление очереди и снятие межпроцессной блокировки проверены воспроизводимыми тестами. Полный ночной сценарий с реальной перезагрузкой компьютера отдельно не проводился.

Исходные документы, распознанные тексты, изображения документов, ключ доступа, журналы, модели и venv в репозиторий не отправляются. Публикуются код, лицензия адаптированного формульного OCR, тесты и агрегированные показатели.
